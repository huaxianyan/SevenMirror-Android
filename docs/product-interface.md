# Android 产品界面

## 当前切片

这是三端重设计中的 Android 第一项实现，不代表 Android 产品化已经全部完成。现有配对、身份、应用选择和权限配置继续使用原存储，不要求清除应用数据或重新注册。

- 主导航为「同步／应用／设置」，宽度从 600 dp 起使用导航栏侧栏布局
- 二级页面维护实际访问栈：顶部返回和系统返回均回到用户进入该页之前的页面；点击一级导航会清空二级访问栈，不按页面所属设置分类跳转
- 同步页展示连接、应用范围、后台配置摘要及问题入口，不将连接成功描述为通知交付成功
- 应用列表展示本机应用图标、名称和完整包名，名称与包名均可搜索，支持分类与已选筛选
- 图标按可见项在后台读取，包已卸载或图标资源不可用时使用通用应用图标，不联网取图
- 应用选择固定在列表底部显式保存，未保存离开时提示继续编辑或放弃
- 配置统一进入设置，全局开关即时保存，应用策略在独立页面显式保存
- 应用策略的正文、持续通知和操作覆盖使用同一个 SharedPreferences editor 提交，展示的生效权限复用既有业务计算
- 设置提供「接收设备」页面，按本手机显式保存浏览器范围，空选择合法；同步页展示选择摘要并直达
- 设置提供独立「权限与运行条件」，已完成设置后失去通知访问不再退回首次引导
- 返回前台时重新查询系统状态，状态通知从系统设置恢复，覆盖无法再次弹出运行时申请的情况
- 状态通知判断由界面与后台服务共用，同时检查运行时权限和应用通知总开关
- 设备列表归入设置，只展示权威成员信息，不冒充实时在线列表
- 开发通知入口仅在 Debug 的独立诊断分区出现
- 主界面从 MainActivity 拆到 AndroidProductScreens，Activity 保留系统入口、生命周期和首次加入流程

旧导航曾将已删除的 MainDestination 枚举写入界面恢复状态。本切片给 Activity 界面状态增加版本标记，升级时丢弃旧 UI 快照，不触碰身份或配置存储。新主导航及二级访问栈按字符串保存，避免绑定枚举的序列化类名。升级后可能回到同步首页，而不是原页面。

## 业务边界与待办

- 接收设备选择已实现：新配置及没有显式记录的旧配置默认空选择，已有显式选择原样读取；实时发送、主动快照、补发时生成的新密文、快照请求响应和新远程操作均受选择约束。发送范围取保存选择与当前有效浏览器成员的交集，新批准浏览器不自动加入
- 取消选择不撤回已经提交或排队的密文；已有操作结果和确认仍允许完成收尾
- 真正的业务暂停／恢复已实现：首页立即暂停新通知发送、删除、快照响应和新远程操作，不释放 Activity 或后台服务持有的连接；恢复时按当前活动通知、应用策略和接收设备发送快照对账，重启后保留暂停状态
- 暂停前已执行的操作、已提交密文、操作结果及确认继续收尾，不宣称远程撤回
- 首次加入完整流程的新布局、外观与语言设置细节
- 真机字体缩放、TalkBack、深色模式、横屏、升级恢复和新页面操作验收
- 已知网络切换长等待及未完成的后台可靠性矩阵

接收范围与暂停均在 Android 发送和操作执行边界生效，不用浏览器本地隐藏冒充手机侧控制。后台同步开关仍只控制退出应用后的连接 owner，与业务暂停保持两个独立概念。接收设备页面只展示当前有效且有接收资格的浏览器，权威成员资格仍由管理端维护。

## 构建基线

Google Maven 元数据已核实稳定 Compose BOM 为 `2026.08.00`，Material 3 为 `1.4.0`。BOM 在 app 中单点声明，复用于产品和界面测试。依赖锁、Release runtime inventory 及 SHA-256 验证元数据同步维护。

Compose 1.12 的 AAR 元数据要求 compileSdk 至少 37。SDK 仓库的实际包名使用小版本，本切片采用稳定的 `platforms;android-37.2` 和 AGP `release(37) { minorApiLevel = 2 }`，而不是不存在的 `platforms;android-37`。本机安装在共享 Android SDK。minSdk 仍是 29，targetSdk 仍是 35，Java 17 和现有 Kotlin/KAPT 防护不变。

参考：

- [Compose Material 3 发布说明](https://developer.android.com/jetpack/androidx/releases/compose-material3)
- [Compose BOM 元数据](https://dl.google.com/dl/android/maven2/androidx/compose/compose-bom/maven-metadata.xml)

## 验证边界

本地运行 app 的 Debug／Release 单元测试、Debug lint、Debug APK 和界面测试 APK 构建。新增 API 29 仪器测试纳入现有 CI，保留原 crypto、notification 和 transport 检查。

- 一个真实生产 Compose 主界面的集成测试，固定应用目录与平台状态夹具，覆盖暂停／恢复、应用设置归属、接收设备保存、未保存提醒和权限页面恢复
- 一个真实偏好存储的模块测试，验证应用正文、操作配置和暂停状态可以一起保存并重新读取
- 单元测试验证已完成设置后的权限丢失仍保留主导航，以及中等宽度的导航布局

界面测试直接挂载生产主界面，平台状态由测试提供，不是完整注册端到端测试，也不证明真实系统权限申请、手机通知交付或真机视觉质量。本轮不自动安装手机、不切网、不更新 Shiva。此文不以本地构建替代最终 SHA 的必需 CI。
