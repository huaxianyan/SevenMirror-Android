# 通知稳定等待

## 目标与默认值

Android 在加密发送前合并短时间内的通知变化，减少应用修改通知或通知过滤软件处理时产生的浏览器闪烁。
本轮只修改 Android，服务端、扩展和协议保持不变。

「设置 → 同步默认设置 → 等待通知稳定」控制是否启用等待。
新安装默认关闭；已完成欢迎流程且尚无开关选择的旧测试配置，首次升级保存为开启。
随后始终保留用户显式选择，包括关闭。迁移只写该开关，保留配对、接收设备及应用配置。
应用启动时读取保存选择，后台同步与前台使用同一控制器配置。

关闭后新增、更新和普通移除立即同步，待定内容重新按当前策略处理，并取消等待任务与释放短时唤醒锁。
开启后使用以下固定数值，已有发布内容保留，后续变化进入稳定等待。

- 新增与内容更新：从最后一次有效变化起等待 1000 毫秒
- 已同步通知的普通移除：等待 300 毫秒，同一通知重新出现时合并处理
- 尚未同步的通知在等待期间消失：取消待定内容
- 权限失效、同步对象取消和隐私策略变更：立即处理，取消相关待定任务

等待按系统通知 key 独立管理，其他通知的变化不重置该条的计时。
内容完全相同的重复回调保留已有判定，不延长等待，并使用应用最新的操作对象。
持续发生有效修改的通知会继续等待稳定，不设置强制发布上限。
本轮没有新增自定义数值界面。日常使用发现默认值不合适后，可在 Android 设置增加配置。
不同通知 key 的取消与发布保持独立，不通过标题或正文猜测它们属于同一条通知。

## 状态与快照

`LocalNotificationController` 分别维护手机当前通知、已发布镜像和待定变化。
已发布镜像只有一份权威状态，实时发送与恢复快照都读取它。

普通更新等待期间，快照保留已发布版本，不提前包含待定内容。
最终发布时分配新 revision，使其高于等待期间可能形成的快照 high-water。
监听器首次取得活动集合时，完整快照等待待定变化收敛，避免先发空集合再恢复通知。
该期间快照查询暂时返回未就绪，已稳定的通知仍可各自发布。
若活动通知持续修改，首次完整快照也会继续等待该批变化收敛。

手机移除通知后立即撤销其操作资格，浏览器展示可保留到短缓冲结束。
内容变化立即使旧版本操作失效，新版本操作在正式发布后可用。
分组、容量及应用选择决定的同步资格立即更新，不受展示缓冲影响。

## 熄屏与生命周期

任务使用主线程 Handler，回调执行时重新检查最新选择及策略。
开关开启时，短等待使用 `WAKE_LOCK` 正常权限和有超时的 partial wake lock，避免熄屏时 CPU 挂起拖延任务。
每次调度设置 2 秒超时，待定任务全部完成或监听器清理后立即释放。
新的有效变化可以续用该短窗口，不创建永久保活锁或新的后台服务。

监听器失效会取消所有本轮待定回调、清理状态，并沿用已有空快照收敛行为。
待定计时不写入持久化存储。进程重启后，监听器重新读取系统实际活动通知并重新稳定。
该机制不能撤回已经提交到发送队列的通知，也不能保证拦住超过等待窗口才被过滤的通知。

## 验证范围

仪器测试使用真实通知提取和控制器入口，覆盖快速移除、连续修改、取消重发、普通删除及恢复版本关系。
既有同步策略、分组、监听器失效与加密操作测试保留，等待相关用例显式启用开关。
既有场景覆盖关闭时发布待定内容，以及关闭后的即时更新与移除。
产品页面验证开关入口，配置测试覆盖新安装、旧测试配置迁移及显式选择保留。
本地统一验证与必需 CI 使用既有测试集，仪器测试仅在模拟器运行。
用户设备仍需同签名升级后的产品流程验收，不以模拟器结果替代日常通知过滤效果。
